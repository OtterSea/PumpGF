# 项目文件夹规范（Project Folder Convention）

> 本文件定义 **基于 PumpGF 的业务项目** 的 `Assets/` 顶层文件夹布局约定，以及一份**可直接让 AI 生成的脚手架清单**。
> 用途：项目"初始化"的一环——AI 读取本文件即可直接创建规范化文件夹，人类也能一眼看懂工程结构。
>
> 维护方式：本文件属于 PumpGF 框架（作者自有、可改）。如要增删文件夹，直接编辑本文件；如涉及编码/宪法层面约束，走对应通道。
> 关联：通用编码规范见 [constitution.md](./constitution.md)；工作流见 [speckit/speckit工作流.md](./speckit/speckit工作流.md)。

---

## 0. 命名约定（个人习惯，非强制分类）

- **`_` 前缀可有可无**，是作者个人习惯，不作强制分类：
  - 储备 / 辅助类常带 `_`：`_Arts`（原始美术储备）、`_ProjectDocs`（AI 上下文）。
  - 玩法 / 工程必需根目录常不带 `_`：`Resources`、`Plugins`、`Scripts`、`Editor`、`Settings`。
  - 特例：`_Res` 虽带 `_`，但属必需目录（与 `_Arts` 对应命名），以习惯为准。
- **复数形式**：文件夹名用复数（加 `s`）表达"内容集合"语义。例外：Unity 保留名须保持原拼写（`Editor`、`Resources`）；缩写 `_Res`（Resources 缩写）保持原样。

> 目标：先定下"几乎不会改变"的大文件夹结构，之后开发尽量不再在 `Assets` 下新建顶层目录。

## 1. 文件夹职责表

| 文件夹 | 用途 | 是否进包 | 依赖关系 | 备注 / 注意 |
|--------|------|----------|----------|-------------|
| `Assets/_Arts` | 原始美术资源库：图片、模型、原始分轨等 | **不自动进包**（仅被 `_Res` 引用时才随包打入） | 被 `_Res` 依赖 | 储备性质，可能长期不被游戏使用 |
| `Assets/_Res` | 需要进包、要做**分包（AB 包）**的内容；游戏实际使用的资源 | 进包（按 AB 包分包） | **依赖 `_Arts`**（打包时把所需 `_Arts` 资源一并打入） | gameplay prefab、音频成品、SO 配置、场景等放其下子目录 |
| `Assets/Resources` | **直接打进安装包、不可分包**、自包含的内容 | 永远全量进包 | 不依赖包外任何东西（包外可依赖它） | Unity **保留名**；放"永远必需且被外部依赖"的：字体、SDF、登录界面 UI 等 |
| `Assets/Plugins` | 仅针对**当前游戏**的第三方库 / 原生插件 | 进包 | 无 | Unity **保留名**；平台原生插件按子目录放：`Plugins/Android`、`Plugins/iOS`、`Plugins/x86_64`… |
| `Assets/Scripts` | 项目绝大多数 C# 代码 | 进包 | — | `_Arts` 与 `Resources` 内**不写业务代码** |
| `Assets/Editor` | 当前项目专属的编辑器可视化工具（给人查阅/操控用） | **不进包**（仅编辑器） | — | Unity **保留名**；文件夹名为 `Editor` 即自动编辑器专用，代码不进包 |
| `Assets/_ProjectDocs` | AI 上下文与产出（SpecKit 工作流产物、愿景、学习笔记等） | 不进包 | — | 见 [`Assets/_ProjectDocs/README.md`](../../Assets/_ProjectDocs/README.md) |
| `Assets/Settings` | URP 初始化生成的配置 | 进包 | — | 保持默认，勿手改 |

### `_Res` 推荐子目录（均不另置于 `Assets` 根）

| 子目录 | 用途 |
|--------|------|
| `_Res/Scenes/` | 场景文件（启动场景、关卡），由 PumpGF `LevelManager` 管理 |
| `_Res/Audios/` | 音频成品（BGM / SFX），由 `AudioMgr` 播放，打包走 `_Res` 分包 |
| `_Res/Prefabs/` | 游戏实际使用的预制体（美术白模 / 原始 prefab 留 `_Arts`） |
| `_Res/Configs/` | PumpGF `ConfigMgr` 加载的 SO 配置 / 数据表 |

> 注：`_Art` 是 `_Arts` 的简称，引用时等价。

## 2. 打包方式（重要）

- 本项目**不使用 `StreamingAssets`**：资产分包由 **AB 包打包工具**处理 `_Res` 内资产，工具会把 `_Res` 引用到的 `_Arts` 资源一并打入对应包。
- PumpGF 当前打包工具可能尚不完善，此为**计划演进方向**：后续完善 `_Res` 的 AB 分包能力，使其稳定可用（属于对框架的优化，按[项目宪法 · 框架演进策略](../AI编程规范/constitution.md)留痕）。
- `Resources` 走 Unity 原生全量进包（不分包），仅放"永远必需且被外部依赖"的独立内容。

---

## 3. Unity 保留名 / 程序集注意事项（AI 必须遵守）

| 文件夹 | 关键点 |
|--------|--------|
| `Resources` | 全量进包、不可 Addressables / AB 热更；只放"永远需要且不被分包"的内容 |
| `Plugins` | 编译进 firstpass 程序集；子目录 `Android/iOS/x86_64` 有平台语义 |
| `Editor` | 名为 `Editor` 的文件夹 Unity 自动视为编辑器专用，内部 `UnityEditor` 代码不进包；勿把 `UnityEditor` 代码放到其他程序集 |
| （`StreamingAssets`） | 本项目不使用；WebGL 下读取受限，配置不依赖它 |

## 4. 脚手架清单（AI 可直接生成）

> 以下为"项目初始化"时应存在的顶层文件夹。已存在的不重复创建；空文件夹在 Unity 中需有内容（或 `.meta`）才保留，建议每目录放一份 `README.md`（本项目即采用此做法）。
> **执行前先确认：本清单是否覆盖你当前所需，避免多建/漏建。**

**已存在（本项目现状）：**
- `Assets/_Arts/` ✅
- `Assets/_Res/`（含 `Scenes/`、`Prefabs/`；`Audios/`、`Configs/` 已补建）✅
- `Assets/Resources/` ✅
- `Assets/Plugins/` ✅
- `Assets/Scripts/` ✅
- `Assets/Editor/` ✅（由 `EditorTool` 改名）
- `Assets/Settings/` ✅
- `Assets/_ProjectDocs/` ✅

**按需创建（首次初始化时生成）：**
- `Assets/Plugins/Android/`、`Assets/Plugins/iOS/`、`Assets/Plugins/x86_64/`（平台原生插件占位，按需）

> 说明：`_Res` 下的 `Scenes/`、`Prefabs/`、`Audios/`、`Configs/` 子目录已随项目建立；新项目初始化时由 AI 按本清单一并创建。

## 5. 与 SpecKit 初始化的关系

本文件是"项目初始化（scaffold）"的权威依据。流程建议：

1. 新建空 Unity 工程 + 引入 PumpGF。
2. **读取本文件** → 创建 §4 的文件夹脚手架（已存在的跳过）。
3. 进入正常需求开发：大需求走 `constitution → specify → plan → tasks → implement`，小需求走 `simple/simple2`（见 [speckit工作流](./speckit/speckit工作流.md)）。
4. 业务层 SpecKit 产物统一放 `Assets/_ProjectDocs/02_SpecKit工作流/`。

> 人类说"**按 项目文件夹规范 初始化**"，AI 即应执行 §4。
