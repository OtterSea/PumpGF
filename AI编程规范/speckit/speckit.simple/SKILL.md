# SpecKit: Simple — 小需求快速实现

## 用途

针对小需求，一个命令完成分析→方案→实现。适用于改动集中在 1-5 个文件、不涉及新模块/系统架构的需求。产物：`.specify/<主题>/<N>.simple.md` + 实际代码。

## 复杂度阈值（超过任一项建议升级）

| 维度 | 阈值 |
|------|------|
| 涉及文件数 | > 5 个 |
| 新增类/模块 | > 2 个 |
| 跨系统联动 | > 3 个独立系统 |
| 新增事件 | > 2 个 |
| 新增 UI 页面/模块 | 任何 |
| 配置表变更 | 新增表 |

## 工作流

### Step 1: 快速分析（静默）

- 理解需求描述
- 用 Grep/Glob/Read 定位相关文件
- 评估复杂度 → 超标则输出提示并建议 `/speckit.specify`

### Step 2: 输出方案（需确认）

展示精简方案：需求概括、改动清单（文件+改动+理由）、关键决策、风险点。

用 `AskUserQuestion` 询问：
- 确认开始实现
- 需要调整
- 切换完整流程

### Step 3: 实现代码

- 按改动清单逐文件实现
- 遵循 constitution 编码规范
- 自检：事件配对、空引用、代码风格

### Step 4: 记录与总结

写入 `.specify/<主题>/<N>.simple.md`（workflow/date/status + 需求/方案/变更文件表/备注），向用户报告完成。

## 升级路径

复杂度超标或用户主动选择时：
- 整理分析结果到 spec.md 作为初始草稿
- 提示继续 `/speckit.specify` 或 `/speckit.plan`

## 约束

- 不产出独立的 spec/plan/tasks
- 遵循 constitution 编码规范
- 不整读大文件
- 引用真实路径和类名
