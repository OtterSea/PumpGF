# SpecKit: Implement — 代码实现

## 用途

根据 tasks 文档逐任务实现代码，完成从设计到编码的最终落地。唯一有权写业务代码的 skill。实现完成后回写任务状态。

## 前置条件

- `.specify/<主题>/4.tasks.md` 已存在
- 推荐：已跑过 analyze 且无 Critical

## 工作流

### Step 1: 加载上下文

- 读取 tasks / plan / spec 文件
- 读取 constitution 获取编码规范和约束
- 若存在 analyze.md，确认最新版本非 FAIL

### Step 2: 确定执行策略

- 找到当前待执行任务（第一个 ⬜ 状态）
- 检查依赖任务是否已完成
- 制定当前任务实现方案：文件列表、改动内容、执行顺序

### Step 3: 逐任务实现

对每个任务：

1. **开始** — 标记状态 ⬜ → 🔄
2. **编码** — 遵循 constitution 编码规范、项目现有风格
3. **自检** — 代码符合规范？内存泄漏？空引用？命名一致？
4. **完成** — 列出涉及文件和改动说明
5. **回写状态** — 在 tasks.md 中标记 ✅

### Step 4: 阶段汇报

每完成一个阶段输出汇报：已完成任务、新建/修改文件数、下一阶段预告。

### Step 5: 全部完成

- 确保所有任务标记 ✅
- 输出实现总结：文件清单、关键决策说明

## 编码规则

- 不一次性生成所有代码，按任务逐步实现
- 每个任务完成后等待用户确认再继续
- 遇到歧义用 `AskUserQuestion` 询问
- 设计需调整时先说明原因征得同意
- 遵循 constitution 编码规范（日志、异步、事件、资源等）
- 新增文件用 Write，修改用 Edit（先 Read）

## 约束

- 禁止修改生成代码或自动生成的项目文件
- 禁止修改 constitution 标注为禁止修改的文件
- 与 constitution 冲突时停止编码，提示用户
- analyze 存在未放行的 Critical 时拒绝开始

## 异常处理

| 场景 | 处理 |
|------|------|
| 依赖任务未完成 | 提示用户 |
| 代码冲突 | 读最新内容重新制定方案 |
| 需求变更 | 提示重跑 `/speckit.specify` |
| 技术方案需调整 | 征得同意后更新 plan |
| 任务粒度不合适 | 建议重跑 `/speckit.tasks` |
