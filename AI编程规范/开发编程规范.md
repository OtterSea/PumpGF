# PumpGF 开发编程规范

> 本规范适用于所有 PumpGF 框架代码及基于 PumpGF 的业务层代码。
> AI 编程助手在生成代码前**必须**阅读本规范。

> ⚠️ **涉及初始化/跨对象引用/场景关卡加载时**，另**必须**阅读 [`时序竞态与初始化最佳实践.md`](./时序竞态与初始化最佳实践.md)（约束见 [`PumpGF框架约束清单.md`](./PumpGF框架约束清单.md) 铁律 11）：
> 禁止在 Awake/Start 获取运行时动态对象引用、禁止 `WaitUntil` 轮询，必须走 `Readiness` / `SceneBootstrapper` / `IPhasedLevel` 三道防线。

## 核心原则

**Unity 是单线程、GC 敏感的运行环境。** 每一帧只有约 16ms（60fps），一次 GC 卡顿就可能造成可感知的掉帧。因此：

1. **零分配优先** — 热路径（Update、循环、高频事件）中不产生任何堆分配
2. **池化一切** — 动态创建的对象走对象池，不用 `new`，不用 `Instantiate/Destroy`
3. **缓存一切** — 组件引用、数组、委托，获取一次，复用终身

## 等级说明

| 标记 | 含义 |
|------|------|
| 🚫 **禁止** | 绝不可这样做，没有例外 |
| ⚠️ **谨慎** | 需要充分理由才可这样做，必须注释说明 |
| ✅ **推荐** | 应当这样做，是默认选择 |

## 一、对象创建与 GC

### 🚫 禁止在热路径中使用 `new` 创建临时对象

热路径 = `Update`、`FixedUpdate`、`LateUpdate`、R3 `Subscribe` 回调、`foreach` 循环体、每帧执行的方法。

```csharp
// 🚫 每帧分配一个新 List
void Update()
{
    var enemies = new List<Enemy>();
    // ...
}

// 🚫 每帧分配一个新数组
void Update()
{
    var hits = Physics.RaycastAll(origin, dir, dist);
    // RaycastAll 内部 new 了一个数组返回
}

// 🚫 每帧 new 一个临时对象
void Update()
{
    var temp = new Vector3(x, y, z); // Vector3 是 struct，不分配堆内存
    // 但如果是 class 则分配了
    var data = new DamageData();    // 如果 DamageData 是 class → GC
}
```

### ✅ 推荐做法

```csharp
// ✅ 预分配，复用
readonly List<Enemy> enemyBuffer = new(64);

void Update()
{
    enemyBuffer.Clear();
    // 填充 enemyBuffer，不 new 新 List
}

// ✅ 使用 NonAlloc 重载
readonly RaycastHit[] hitBuffer = new RaycastHit[16];

void Update()
{
    int count = Physics.RaycastNonAlloc(origin, dir, hitBuffer, dist);
    for (int i = 0; i < count; i++)
    {
        // 处理 hitBuffer[i]
    }
}

// ✅ 需要动态创建对象时使用对象池
var obj = ObjectPool<ParticleEffect>.Get();
// 使用完毕
ObjectPool<ParticleEffect>.Release(obj);
```

### ⚠️ 谨慎使用 `new`

在以下场景中可以使用 `new`：
- `Awake` / `Start` / 初始化阶段（一次性）
- 事件注册、订阅绑定（不在热路径中）
- 构造 struct（struct 分配在栈上，不产生 GC）
- 容器预分配 `new List<T>(capacity)`

### 🚫 禁止 `Instantiate` / `Destroy` 高频循环

```csharp
// 🚫 每次开枪都 Instantiate 一颗子弹，命中后 Destroy
void Fire()
{
    var bullet = Instantiate(bulletPrefab, pos, rot);
    // ...
}
void OnHit(Bullet bullet)
{
    Destroy(bullet.gameObject);
}

// ✅ 使用对象池
void Fire()
{
    var bullet = BulletPool.Get(pos, rot);
    bullet.Launch();
}
void OnHit(Bullet bullet)
{
    BulletPool.Return(bullet); // 回收，不 Destroy
}
```

## 二、字符串

### 🚫 禁止在热路径中拼接字符串

```csharp
// 🚫 每帧拼接字符串 → 产生大量 GC
void Update()
{
    scoreText.text = "Score: " + score + " / " + maxScore;
    // 等价于 string.Concat(...)，每次都分配新字符串
}

// 🚫 string.Format 在热路径中
void Update()
{
    Debug.Log(string.Format("HP: {0}/{1}", hp, maxHp));
}
```

### ✅ 推荐做法

```csharp
// ✅ 缓存格式化结果，仅在值变化时更新
int lastScore = -1;
void Update()
{
    if (score != lastScore)
    {
        lastScore = score;
        scoreText.text = $"Score: {score} / {maxScore}";
    }
}

// ✅ 大量拼接用 StringBuilder
readonly StringBuilder sb = new(128);
string BuildTooltip()
{
    sb.Clear();
    sb.Append("Name: ").Append(name);
    sb.Append("\nHP: ").Append(hp);
    return sb.ToString();
}

// ✅ Debug.Log 本身有开销，发布构建中应通过 [Conditional] 移除
[System.Diagnostics.Conditional("UNITY_EDITOR")]
void LogDebug(string msg) => Debug.Log(msg);
```

## 三、LINQ

### 🚫 禁止在热路径中使用 LINQ

LINQ 的每个链式调用都会产生闭包和迭代器对象分配。

```csharp
// 🚨 每帧 LINQ → 大量 GC
void Update()
{
    var alive = enemies.Where(e => e.IsAlive).OrderBy(e => e.Hp).FirstOrDefault();
}

// ✅ 手写循环
Enemy target = null;
int lowestHp = int.MaxValue;
for (int i = 0; i < enemies.Count; i++)
{
    var e = enemies[i];
    if (e.IsAlive && e.Hp < lowestHp)
    {
        lowestHp = e.Hp;
        target = e;
    }
}
```

### ⚠️ 谨慎使用 LINQ

- 初始化阶段（Awake/Start）可以使用 LINQ 简化代码
- 非热路径的业务逻辑可以酌情使用
- 使用后不要保留 IEnumerable 引用（会持有底层状态）

## 四、组件引用与查找

### 🚫 禁止在热路径中查找组件

```csharp
// 🚨 每帧 GetComponent → 不分配但开销大
void Update()
{
    var rb = GetComponent<Rigidbody>();
    rb.AddForce(force);
}

// 🚨 每帧 Find → 极慢
void Update()
{
    var player = GameObject.Find("Player");
}

// 🚨 Camera.main 内部调用 FindObjectWithTag
void Update()
{
    var cam = Camera.main;
}
```

### ✅ 推荐做法

```csharp
// ✅ 在 Awake/Start 中缓存
Rigidbody rb;
Camera mainCam;

void Awake()
{
    rb = GetComponent<Rigidbody>();
    mainCam = Camera.main; // 获取一次
}
```

### 🚫 禁止使用 `==` 比较标签

```csharp
// 🚨 分配临时字符串
if (gameObject.tag == "Player") { }

// ✅ 使用 CompareTag
if (gameObject.CompareTag("Player")) { }
```

## 五、容器与数组

### ⚠️ 谨慎创建容器，必须指定容量

```csharp
// ⚠️ 未指定容量，Add 时多次扩容
var list = new List<int>();
for (int i = 0; i < 100; i++) list.Add(i);

// ✅ 预分配容量
var list = new List<int>(100);

// ✅ 更好：如果大小固定，用数组
var array = new int[100];
```

### 🚫 禁止在热路径中调用 `ToArray()` / `ToList()`

```csharp
// 🚨 每帧分配新数组
void Update()
{
    var array = someList.ToArray();
}

// ✅ 直接用索引遍历 List
for (int i = 0; i < someList.Count; i++)
{
    var item = someList[i];
}
```

### ✅ 推荐使用 `stackalloc` 处理小型临时缓冲

```csharp
// ✅ 栈上分配，无 GC
void Process()
{
    Span<Vector3> directions = stackalloc Vector3[8]
    {
        Vector3.up, Vector3.down, Vector3.left, Vector3.right,
        Vector3.forward, Vector3.back, new(1,1,0), new(-1,-1,0)
    };
    // 使用 directions...
}
```

## 六、委托与闭包

### 🚫 禁止在热路径中创建闭包

```csharp
// 🚨 lambda 捕获了外部变量 → 编译器生成闭包类 → 堆分配
void Update()
{
    Observable.EveryUpdate()
        .Where(_ => IsReady)  // 捕获 this → 闭包
        .Subscribe(_ => { }); // 捕获 this → 闭包
}

// 🚨 每帧 new Action
button.onClick.AddListener(() => OnClick());
```

### ✅ 推荐做法

```csharp
// ✅ 缓存委托
readonly Action onClick;
void Awake()
{
    onClick = OnClick;
    button.onClick.AddListener(onClick);
}

// ✅ R3 订阅在初始化时绑定，AddTo 管理生命周期
void Awake()
{
    button.OnClickAsObservable()
        .Subscribe(_ => OnClick())
        .AddTo(this);
}
```

## 七、协程与异步

### 🚫 禁止使用 `yield return new WaitForSeconds()`

```csharp
// 🚨 每次 new 一个 WaitForSeconds 对象
IEnumerator DelayedAction()
{
    yield return new WaitForSeconds(1f);
    DoSomething();
}

// ✅ 缓存 WaitForSeconds（Unity 5.4+ 支持复用）
static readonly WaitForSeconds waitOneSec = new(1f);
IEnumerator DelayedAction()
{
    yield return waitOneSec;
    DoSomething();
}

// ✅✅ 更推荐：直接用 UniTask
async UniTaskVoid DelayedActionAsync()
{
    await UniTask.Delay(TimeSpan.FromSeconds(1f));
    DoSomething();
}
```

### 🚫 禁止使用 `async void`

```csharp
// 🚨 异常无法捕获，会导致进程崩溃
async void DoWork() { ... }

// ✅ 使用 UniTaskVoid + Forget
async UniTaskVoid DoWork() { ... }
void Start() => DoWork().Forget();

// ✅ 需要等待结果时用 UniTask
async UniTask<int> GetDataAsync() { return 42; }
```

### ✅ 推荐使用 UniTask 替代协程

所有异步场景统一使用 UniTask，不再使用 `IEnumerator` 协程。理由：
- 零分配
- 可组合（WhenAll、WhenAny）
- 可取消（CancellationToken）
- 可异常处理（try-catch）

## 八、Update 循环

### ⚠️ 谨慎在 Update 中放置逻辑

Update 每帧执行，性能影响最直接。遵循以下原则：

1. **能不写 Update 就不写** — 用 R3 的 `Observable.EveryUpdate()` 或事件驱动
2. **降频执行** — 不需要每帧执行的逻辑用计数器降频
3. **空 Update 要删** — 空的 Update 方法 Unity 仍然会每帧调用

```csharp
// ✅ 降频执行
int frameCounter = 0;
void Update()
{
    if (++frameCounter % 5 != 0) return; // 每 5 帧执行一次
    // 低频逻辑...
}

// ✅ 值变化时才执行（R3 方式）
Observable.EveryValueChanged(this, x => x.Hp)
    .Subscribe(hp => UpdateHpUI(hp))
    .AddTo(this);
```

### 🚫 禁止在 Update 中使用 `Debug.Log`

`Debug.Log` 内部会格式化字符串、获取堆栈信息，开销极大。开发时用 `[Conditional]` 包裹：

```csharp
[System.Diagnostics.Conditional("PUMPGF_DEBUG")]
static void Log(string msg) => Debug.Log(msg);

void Update()
{
    Log($"Position: {transform.position}");
    // 发布构建中这行代码会被编译器完全移除
}
```

## 九、数学运算

### ⚠️ 谨慎使用 `Mathf` 中的浮点运算

- `Mathf` 内部调用 `UnityEngine.Mathf`，部分方法比 `System.Math` 慢
- 高频数学运算考虑查表或近似

```csharp
// ⚠️ 可以但注意开销
float angle = Mathf.Atan2(y, x) * Mathf.Rad2Deg;

// ✅ 如果同一角度反复计算，缓存结果
float angle;
if (Vector3.SqrMagnitude(prevDir - dir) > 0.0001f)
{
    angle = Mathf.Atan2(dir.y, dir.x) * Mathf.Rad2Deg;
    prevDir = dir;
}
```

### ✅ 推荐用 `Vector3.SqrMagnitude` 替代 `Vector3.Distance`

```csharp
// 🚨 开方运算
if (Vector3.Distance(a, b) < range)

// ✅ 比较平方距离，省去开方
if ((a - b).sqrMagnitude < range * range)
```

## 十、R3 与 UniTask 注意事项

### ✅ 推荐的订阅管理方式

```csharp
// ✅ 单个订阅：AddTo
Observable.EveryUpdate()
    .Subscribe(_ => { })
    .AddTo(this);

// ✅ 多个订阅：DisposableBag（最高效）
DisposableBag bag = default;
Observable.EveryUpdate().Subscribe().AddTo(ref bag);
Observable.IntervalFrame(60).Subscribe().AddTo(ref bag);

void OnDestroy()
{
    bag.Dispose();
}
```

### ⚠️ 谨慎使用 R3 操作符链过深

```csharp
// ⚠️ 超长链虽然功能正确，但难以维护和调试
source
    .Where(x => x > 0)
    .Select(x => x * 2)
    .ThrottleLastFrame(3)
    .DistinctUntilChanged()
    .Buffer(10)
    .Select(xs => xs.Sum())
    .Subscribe();

// ✅ 适度拆分，可读性优先
var filtered = source.Where(x => x > 0).Select(x => x * 2);
var sampled = filtered.ThrottleLastFrame(3).DistinctUntilChanged();
sampled.Buffer(10).Subscribe();
```

### ✅ UniTask 取消传递

```csharp
// ✅ 所有异步方法传递 CancellationToken
async UniTask LoadAsync(CancellationToken ct)
{
    await Resources.LoadAsync<TextAsset>("data").WithCancellation(ct);
}

// ✅ 使用 MonoBehaviour 的 destroyCancellationToken
async UniTaskVoid DoWorkAsync()
{
    await LoadAsync(destroyCancellationToken);
}
```

## 速查表

| 禁止 🚫 | 替代方案 ✅ |
|---------|-----------|
| `new List<T>()` 在 Update 中 | 预分配字段 + Clear + 复用 |
| `GetComponent<T>()` 在 Update 中 | Awake 中缓存 |
| `GameObject.Find()` 在 Update 中 | Awake 中缓存或事件引用 |
| `Camera.main` 在 Update 中 | Awake 中缓存 |
| `tag == "Player"` | `CompareTag("Player")` |
| `"a" + b + "c"` 在热路径中 | StringBuilder 或仅变化时更新 |
| `LINQ` 在热路径中 | 手写 for 循环 |
| `ToArray()` / `ToList()` 在热路径中 | 直接遍历源集合 |
| `Instantiate` / `Destroy` 高频 | 对象池 |
| `yield return new WaitForSeconds()` | UniTask.Delay 或缓存 WaitForSeconds |
| `async void` | `async UniTaskVoid` + `.Forget()` |
| `Physics.RaycastAll()` | `Physics.RaycastNonAlloc()` |
| lambda 闭包在热路径中 | 缓存委托字段 |
| `Debug.Log` 在 Update 中 | `[Conditional]` 包裹 |
| 空的 Update 方法 | 删除它 |
| `Vector3.Distance` 比较距离 | `sqrMagnitude` 比较平方距离 |

## 新增模块时的检查清单

编写 PumpGF 模块代码时，逐条检查：

- [ ] 热路径中零堆分配？（无 new class、无 LINQ、无字符串拼接）
- [ ] 动态对象走对象池？（无裸 Instantiate/Destroy）
- [ ] 组件引用已缓存？（无热路径中的 GetComponent/Find）
- [ ] 异步用 UniTask？（无协程 IEnumerator）
- [ ] 事件用 R3？（无 C# event 在高频场景）
- [ ] 订阅有生命周期管理？（AddTo / DisposableBag）
- [ ] 容器预分配容量？
- [ ] Update 中无 Debug.Log（或用 Conditional）？
- [ ] 值比较用 CompareTag？
- [ ] 数学运算避免重复开方？
