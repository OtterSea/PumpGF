# PumpGF 踩坑记录

本文档收录 PumpGF 框架开发过程中曾经踩过的坑，供 AI/人类开发者参考避免。

**AI 编码时如遇到相同错误，请优先按此清单排查。**

> ℹ️ **背景说明**：本文档中"坑 1 ~ 坑 8"绝大多数是**作者早期误用 Unity 2021 打开框架时踩出来的兼容性坑**。当前 PumpGF 已明确只支持 **Unity 2022.3 LTS**（详见 [`README.md`](../README.md)），这些坑在 Unity 2022 LTS 环境下大多不再复现。保留在这里是作为历史记录，同时防止 AI 生成代码时无意间用回 Unity 2021 的写法。

---

## 1. R3.Subject / R3.Observable ≠ System.IObservable

R3 为了性能，**没有让 `Observable<T>` 继承 `System.IObservable<T>`**。它们是两套 API。

- 编译错误：`error CS0266: Cannot implicitly convert type 'R3.Subject<T>' to 'System.IObservable<T>'`
- ✅ 正确：对外暴露事件流用 `R3.Observable<T>`（`Subject<T>` 可隐式转换为它），而不是 `System.IObservable<T>`。
- ❌ 错误：用 `System.IObservable<T>` 做返回类型或字段类型。

## 2. Unity 2021 缺少 GameObject.destroyCancellationToken

- Unity 2022.2+ 才有 `Component.destroyCancellationToken` / `GameObject.destroyCancellationToken`。
- Unity 2021 编译错误：`error CS1061: 'GameObject' does not contain a definition for 'destroyCancellationToken'`
- ✅ 兼容方案（若必须支持 2021）：改用 UniTask 提供的扩展 `owner.GetCancellationTokenOnDestroy()`（见 [`AsyncTriggerExtensions.cs`](../Vendor/UniTask/Runtime/Triggers/AsyncTriggerExtensions.cs)）。
- ✅ 推荐方案：直接强制 Unity 2022.2+（本框架的做法）。**AI 生成新代码时优先使用 `destroyCancellationToken`。**

## 3. UniTask.DOTween 扩展默认关闭

- `Vendor/UniTask/Runtime/External/DOTween/DOTweenAsyncExtensions.cs` 原始版本包在 `#if UNITASK_DOTWEEN_SUPPORT` 内，宏由 `UniTask.DOTween.asmdef` 通过 `versionDefines` 检测 UPM 包 `com.demigiant.dotween` 是否安装来触发。
- 本框架用源码方式引入 DOTween（`Vendor/Demigiant/`），**不通过 UPM 安装**，所以宏永远不会被定义 → `Tween.ToUniTask()` 找不到 → 各 `.DOFade(...).ToUniTask(ct)` 全部报错。
- ✅ 已修复：改造 [`UniTask.DOTween.asmdef`](../Vendor/UniTask/Runtime/External/DOTween/UniTask.DOTween.asmdef)，直接引用 `DOTween-Scripts`；同时移除 `DOTweenAsyncExtensions.cs` 里的 `#if/#endif` 包裹。

## 4. TMP_Settings.defaultFontAsset 只读

- Unity 版本更新后 `TMP_Settings.defaultFontAsset` 变为只读属性，不能直接赋值。
- ✅ 现改为：切换语言时通过 `LocalizationMgr.OnFontChanged` 事件通知业务层，业务层自行遍历 `TMP_Text` 组件更新字体。

## 5. UnityEngine.Object 与 System.Object 命名歧义

- 在同时 `using UnityEngine;` 和写了 `System.Object`（或 `object` 隐式）的文件里，`Object.Destroy(...)` / `Object.DontDestroyOnLoad(...)` 会产生歧义。
- ✅ 用 `using UObject = UnityEngine.Object;` 别名 + 显式 `UObject.Destroy(...)`。

## 6. Addressables 相关命名空间容易漏

- `Addressables` 类在 `UnityEngine.AddressableAssets`
- `AsyncOperationHandle` 在 `UnityEngine.ResourceManagement.AsyncOperations`
- `SceneInstance` 在 `UnityEngine.ResourceManagement.ResourceProviders`

三者常一起用，缺一个就报 `CS0246` / `CS0103`。

## 7. UniTask 是 struct，不能用 `??=`

- `UniTask` 是值类型，不是引用类型。写 `_initTask ??= InitCoreAsync()` 会报错。
- ✅ 用 `UniTask?` 可空包装 + 手动 `if (_initTask == null)` 判空。

## 8. ResMgr.LoadAssetAsync 泛型约束

- `LoadAssetAsync<T>` 内部走 Addressables，约束 `T : UnityEngine.Object`。
- 如果外层接口（如 `IConfigProvider.LoadConfigAsync<T> where T : class`）比这个宽松，需要在实现里先按 `UnityEngine.Object` 加载再向下转型。

## 9. R3 核心 DLL 的 Editor 平台勾选

R3 的三个核心 DLL 内置在 [`Vendor/R3.Unity/Runtime/Plugins/`](../Vendor/R3.Unity/Runtime/Plugins)：

- `R3.dll`
- `Microsoft.Bcl.AsyncInterfaces.dll`
- `Microsoft.Bcl.TimeProvider.dll`

这三个 DLL 的 `.meta` 文件里必须把 `Editor` 平台设置为 `enabled: 1`。如果被误关闭，会出现类似：

```
UnityFrameProvider.cs(1,10): error CS0234: The type or namespace name 'Collections' does not exist in the namespace 'R3'
```

的编译错误。

- ✅ 修复方法：在 Unity Inspector 里选中三个 DLL，把 `Editor` 平台勾选启用，或者直接编辑对应 `.meta` 文件。

## 10. RuntimeInitializeOnLoadMethod 时机过早导致 MonoBehaviour 不工作

**背景**：[`GameGlobal.cs`](../Runtime/Core/GameGlobal.cs) 使用 `[RuntimeInitializeOnLoadMethod]` 在游戏启动时自动创建 `LifecycleDriver`（MonoBehaviour），用于驱动框架的 Tick 生命周期。

**错误现象**：在 **Editor** 里一切正常，但 **Standalone Build（exe）** 后，`LifecycleDriver.Update()` 从未被 Unity PlayerLoop 调用，导致所有注册到 `LifecycleMgr` 的 Tick 回调（包括输入采样、FSM、Combat 等）全部静默失效。外在表现为：角色完全无法操控，WASD 无响应，但无任何报错日志。

**原因**：原代码使用 `RuntimeInitializeLoadType.AfterAssembliesLoaded`。该时机位于 Unity 启动序列的最早期——此时 **Unity PlayerLoop 尚未初始化**。在这个阶段通过 `new GameObject()` + `AddComponent<MonoBehaviour>()` 创建的对象虽然实例化成功，但 Unity 不会将其纳入 PlayerLoop 的 Update 调度列表。Editor 下不受影响是因为 Editor 的 PlayerLoop 管理方式不同。

**修复方案**：

```csharp
// ❌ 错误 — 太早，PlayerLoop 未就绪
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]

// ✅ 正确 — PlayerLoop 已就绪，Scene 尚未加载
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
```

**适用场景规则**：
- 需要创建 `GameObject` / `MonoBehaviour` 的初始化 → 至少用 `BeforeSceneLoad`
- 纯静态数据/字典的初始化 → 可用 `AfterAssembliesLoaded`（不涉及 Unity 引擎对象）
- 需要引用场景中已有 GameObject → 用 `AfterSceneLoad`

**发现日期**：2026-07-19

## 附录：其他引擎的已知不兼容项（非官方支持）

以下内容并非踩坑，而是**在非官方支持的引擎版本上确定不能正常工作**的技术记录，供有兴趣做迁移的高级用户参考。

### 团结引擎 Tuanjie 1.9.x

- 团结引擎会把 `Microsoft.Bcl.AsyncInterfaces`、`Microsoft.Bcl.TimeProvider` 等 BCL 程序集视为**引擎内置模块**，**不允许 `Plugins/` 目录再加载同名 DLL**
- 框架内置在 [`Vendor/R3.Unity/Runtime/Plugins/`](../Vendor/R3.Unity/Runtime/Plugins) 里的三个 R3 相关 DLL 会引发加载冲突，导致团结引擎项目无法正常打开
- R3 官方对此类场景建议使用 [NuGetForUnity](https://github.com/GlitchEnzo/NuGetForUnity) 从 NuGet 源安装 R3
- 如果确认要在团结引擎里使用 PumpGF，具体迁移步骤请参考 [`README.md` 附录](../README.md) 相应章节

### Unity 2021 及更早

- 缺少 `GameObject.destroyCancellationToken`（见坑 2）
- 缺少 `Dictionary.Remove(key, out value)` 等 API
- 不支持 C# 9 的 target-typed new、record 等语法
- 会产生近 40 处编译错误，**不建议尝试**
